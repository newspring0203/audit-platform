# 로컬 MVP 실행과 완료 범위

프로젝트 위치: `/Users/saebom/audit-platform`

```bash
cd /Users/saebom/audit-platform
.venv/bin/python scripts/run_local.py
```

http://127.0.0.1:8000/ 을 열고 `.runtime/reviewer.token`을 로컬 편집기로 열어 연결 칸에 입력합니다. 값은 채팅·Git에 보내지 마세요. 실행기는 유효한 토큰을 재사용하고 만료되면 새로 발급합니다. 포트가 사용 중이면 기존 서버를 종료하거나 AUDIT_PORT로 변경합니다. 시작·종료 시 만료된 작업을 보관 정책에 따라 정리합니다. 실행 환경은 프로젝트의 기존 .venv를 사용합니다.

## 사용 순서

1. 연결 후 기능을 선택합니다. 일반 폼에 기간·분석 조건을 입력합니다. 고급 JSON 입력도 유지합니다.
2. 작업을 만들고 필수 입력 슬롯에 파일을 업로드합니다. 필요한 컬럼을 펼치거나 빈 CSV 서식을 내려받습니다. 서식은 입력 컬럼 헤더로 구성됩니다.
3. 자료의 기간/PBC 참조를 입력합니다. 필수 파일을 모두 올리면 분석 실행 버튼이 활성화됩니다.
4. 내 작업 목록에서 작업을 다시 열 수 있습니다. 목록은 현재 사용자 소유의 미만료 작업만 보여줍니다.
5. 분석 완료 후 요약 카드·결과 표·전기/당기 또는 입출고 비교 막대를 확인합니다. 막대는 현재 페이지 최대 8개 항목, 행 내부 절댓값 상대 비교이며 부호·통화는 수치를 함께 확인합니다. 막대의 비교 범위는 화면에 표시된 행입니다.
6. 결과 행에서 원본·계산 조건을 확인하고 검토 기록·기준서 참조를 연결합니다.
7. 분석 ZIP과 최신 검토 이력 JSON을 각각 다운로드합니다. 검토 기록은 분석 시점 ZIP과 분리해 보관합니다.

TB 부호 기준은 기본 미확인입니다. 자료의 차변 양수/대변 음수 기준을 확인한 경우에만 선택하세요. 서버가 폼 숫자·날짜·선택값을 다시 검사하며 누락 조건은 기존 모듈의 검토 보고로 처리합니다.

## 구현된 백엔드·프론트엔드

- FastAPI 작업 생성/목록/입력/실행/상태/결과/출처/검토/다운로드/삭제 API
- Python 분석 엔진, 제한 시간의 작업 프로세스, 사용자별 임시 저장소
- 기능별 입력 폼·입력 컬럼 안내·빈 CSV 서식·업로드·진행 상태
- 결과 카드·비교 표와 막대·자료 버전 비교·원본 추적·검토 이력·기준서 수동 참조
- 사용자 소유권·만료·다운로드 권한·no-store·토큰 메모리 보관

이 문서는 **로컬 개발 모드**의 실행 안내입니다. 공개 데모의 별도 쿠키 인증·배포 조건은 deployment.md와 Backend README를 참고합니다.

## 명확히 남은 작업

- SAP BSEG·BKPF·GLT0 전처리는 웹 업로드 API에 연결되어 있습니다. JET·분석적 검토 등은 전처리된 GL/TB를 입력받습니다. QuickBooks 평탄화는 웹에서 실행하며 ADS 매핑은 후속 변환으로 구성합니다.
- 실제 SAP/QuickBooks 파일 다양성, 통화·금액 기준, 추출 완전성 검증
- KYC 실제 키 호출 검증. AI는 서버에서 기본 비활성화
- 기능별 전용 Excel 구성과 더 깊은 시각화
- 정식 SSO/OIDC·조직 공유 권한·TLS·배포·암호화 보관·백업/삭제 운영 정책
- 기준서 RAG·로컬 LLM·증빙 OCR·매출 실증절차 전체(매출채권 조회 회신 비교는 구현)

사용량을 아끼려면 현재 MVP를 먼저 로컬에서 사용하고, 실제 자료로 발견한 문제를 한 번에 묶어 수정하는 것이 다음 단계입니다. 로컬 실행 검증과 공개 서버 검증은 별도 기록으로 구분합니다.

## 파일·자료 정보 자동 저장

작업 생성 후 파일을 선택하면 순차 자동 업로드합니다. 자료 메모 기간·PBC는 입력 후 자동 저장됩니다. 저장 중·실패·불완전한 기간에는 분석 실행을 막습니다. 분석 조건(연도·TB 회계기간)은 파일 메모 기간과 별도입니다. 파일 메모 기간·PBC는 자료 관리 정보로 보관하고 거래 선택은 분석 조건에서 처리합니다.
