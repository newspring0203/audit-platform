# AICPA ADS GL 학습과 구현 적용

AICPA ADS 영문 명세를 읽고 GL 관련 4개 데이터셋의 69개 필드를 개인 학습 노트로 정리했습니다. 데이터셋별 역할과 필드의 의미를 이해하고, 이를 SAP 전처리·GL 분할·검증 로직에 적용했습니다.

## 학습한 데이터 구조

| 데이터셋 | 정리한 필드 수 | 역할 |
|---|---:|---|
| GL_Detail | 31 | 전표 상세·금액·입력자·회계 반영일과 입력일 |
| Chart_Of_Accounts | 13 | 계정과목의 의미·분류·재무제표 표시 항목 |
| Trial_Balance | 19 | 기간·통화별 기초 및 기말 잔액 |
| Source_Listing | 6 | 전표 출처·관련 시스템·생성 방식 |

69개는 위 GL 관련 4개 데이터셋에서 학습한 필드의 합계입니다.

## 학습을 구현에 적용한 사례

| 학습한 구조 | 적용한 기능 | 코드 |
|---|---|---|
| 거래 내역과 잔액 자료의 연결 | SAP 자료에서 GL·TB를 생성하고 기간별 움직임 대사 | [SAP 변환](../../src/audit_data_lab/sap.py) |
| 회계 반영일과 시스템 입력일의 차이 | 전기일과 입력일을 별도 보존 | [SAP 변환](../../src/audit_data_lab/sap.py) |
| 거래 입력자 정보의 활용 | 입력 사용자별 GL 행 분할 | [사용자별 분할](../../src/audit_data_lab/gl_split.py) |

## 구현 과정에서 구분한 의미

필드 이름을 맞추는 것과 회계적 의미를 확인하는 것은 별개의 작업입니다. 다음 항목은 분석 조건을 정하고 결과를 해석할 때 구분했습니다.

| 구분 | 분석·검토 시 확인할 내용 | 현재 적용 범위 |
|---|---|---|
| 회계 반영일과 입력일 | 회계 반영일이 10월 31일이고 입력일이 11월 2일일 수 있습니다. 날짜 차이를 후속 검토 단서로 활용합니다. | SAP 변환에서 두 날짜를 별도로 보존합니다. |
| 계정 성격과 재무제표 표시 | `Account_Type`의 자산·부채 분류와 `FS_Caption`의 재무제표 표시 항목은 구분합니다. | 전체 계정과목·표시 항목 연결은 후속 과제입니다. |
| 기초·변동·기말 잔액 | 기초잔액에 기간 순변동을 더해 기말잔액과 비교할 때 동일한 범위·통화·차대 부호로 비교합니다. | SAP GL·TB 변환과 기간별 움직임 대사에 적용했습니다. |
| 전표 생성 방식과 통제 방식 | 전표 생성 방식과 통제 방식의 의미를 각각 확인합니다. | `Source_Listing` 전체 연결은 후속 과제입니다. |
| 입력자와 사용자 상태 | 입력자 정보와 거래 입력 당시의 사용자 상태를 함께 검토합니다. | 사용자별 분할은 구현했으며, 사용자 상태 이력 검사는 후속 과제입니다. |

## 학습의 적용

ADS의 필드 정의를 바탕으로 자료 구조를 정리하고, 추출 범위·통화·계정 의미를 변환과 검증 조건에 반영했습니다.
