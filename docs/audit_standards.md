# 프로젝트 기준과 구현 상태

확인일: 2026-10-31. 소프트웨어 설계 기준이며 감사업무 자체의 기준 준수 또는 인증을 의미하지 않습니다.

## 기준의 역할

| 기준 | 사용 목적 | 적용 범위와 주의 |
|---|---|---|
| AICPA ADS General Ledger July 2015 | GL·TB·계정과목표·출처 목록의 필드와 의미, 데이터 프로파일링 | 사용자가 제공한 2015년 GL 문서를 데이터 구조의 기준 버전으로 고정. ADS 전체·Base Standard 검증은 미완료 |
| PCAOB AS 1105 | 감사증거의 관련성·신뢰성, 회사 정보의 정확성·완전성 및 목적에 필요한 상세 수준 확인 | .10과 .29를 참고. 해당 감사업무에 PCAOB 기준이 적용되는지는 별도 판단 |
| AICPA AU-C 500 / SAS 142 관련 자료 | AICPA 감사증거 평가 관점의 참고 | AICPA SAS는 일반적으로 nonissuer 감사에 적용. PCAOB와 동일한 적용 대상·문구라고 취급하지 않음 |

AICPA ADS는 감사기준(AU-C)을 대신하지 않습니다. SAP 필드명·회계 설정도 ADS와 별도로 확인합니다. PCAOB와 AICPA 감사기준을 동시에 충족했다고 표시하지 않습니다. 실제 업무에서는 적용 국가·감사기준·법인 방법론·기준 시행일을 지정해야 합니다.

AICPA 공식 현재 유효 SAS 안내는 2026년 8월 현재 편찬본을 안내합니다. 이 프로젝트는 해당 편찬본 전체 또는 AU-C 500 최신 전문을 문단별 대조한 상태가 아닙니다. 아래 세부 소프트웨어 규칙은 프로젝트의 설계 결정이며 모든 기준에 같은 문구로 규정되어 있다고 주장하지 않습니다.

## 소프트웨어 요구사항 및 상태

| ID | 프로젝트 요구사항 | 기준과의 연결 | 현재 상태 |
|---|---|---|---|
| ADS-01 | ADS 필드명뿐 아니라 의미·형식·코드값 확인 | ADS GL 2015 데이터 사전 | 부분 구현. 통화·사업단위·역분개 등 추가 확인 필요 |
| EVD-01 | 원본과 변환 결과의 행 수·금액·연결 누락을 확인 | AS 1105.10 정확성·완전성 평가를 지원 | SAP 예제 검사 구현. 업무 목적에 충분한지는 감사인이 판단 |
| EVD-02 | 금액 필드·통화·회사·기간·원장 등 대사 기준이 미확보되면 해당 대사 중단 | AS 1105.10/.29를 참고한 프로젝트 정책 | 로그 기준 게이트 구현. 미실행 사유·후속 검토를 조서로 반환 |
| EVD-03 | 사용자 통화 선택·체크박스만으로 기준 확인 완료 처리하지 않음 | 정보 신뢰성 평가를 지원하는 프로젝트 정책 | 확인 모델·근거 파일/입력 지문 검사 구현. 웹 승인 권한·이력 저장은 미구현 |
| EVD-04 | 기준 미확보·확인 후 차이·확인 후 일치를 별도 상태로 보고 | 정보 불충분과 검사 결과를 구분하는 프로젝트 정책 | 상태 구분 구현. 과거 결과에 사용 제한 표시 |
| DOC-01 | 원본·추출 조건·매핑 버전·실행 식별자·확인 근거·검토 기록 보존 | 추적 가능성을 위한 프로젝트 설계 | 원본 보존·실행 폴더·일부 출처 구현. 전체 검토 이력 미구현 |
| JUD-01 | 탐지 후보와 오류·부정·감사 결론을 구분 | 감사인의 증거 평가를 지원 | 안내 문구 구현. UI·권한·검토 워크플로 미구현 |

위 표는 정확성·완전성에 필요한 모든 검사 목록이 아닙니다. GL·로그 금액 대사 한 가지가 통과했다고 모집단 완전성이나 감사증거 충분성을 확정할 수 없습니다.

## 금액 대사 중단 정책

1. 사전 정보 확인: 데이터 출처, 회사·원장·기간, 금액 정의, 통화 기준, 부호·집계 단위, 추출 조건·시점.
2. 누락 시 해당 금액 대사를 실행하지 않고 `basis_information_missing`으로 보고. 차이 0건 또는 통과로 표시하지 않음.
3. 회계·ERP 담당자가 추출 명세·보고서 설정·필드 설명 등 근거를 제공하고 확인자·확인일·적용 범위를 기록.
4. 감사 담당자가 근거의 적절성과 데이터 정확성·완전성 확인 절차를 검토.
5. 확인된 기준으로 새 실행을 생성. 독립적으로 신뢰할 수 있는 다른 검사는 상태·한계를 표시하여 별도 수행 가능.

이 흐름은 구현할 정책입니다. 근거가 제출됐다는 사실과 근거가 적절하다고 검토됐다는 판단을 구분해야 합니다.

## 발견된 로그 문제

`adapt_legacy_log`가 통화 없는 로그에 USD를 붙인 기존 가정은 근거가 부족합니다. 현재 JET 코드는 기준 미확보 시 해당 대사를 실행하지 않고 조서에 사유를 반환합니다. 과거 잘못된 가정의 결과에는 사용 제한을 표시했습니다. 기존 보고서의 10개 차이를 회계 오류 건수로 인용하지 않습니다.

관련 진단은 `outputs/validation/jet_log_review/review.md`에 있습니다. 8개 그룹은 금액 기준이 다른 비교이고, 2개 그룹은 같은 전표 양측의 0.02 잔여 차이입니다. 원인은 확정하지 않았으며 기준 미확보 상태 자체는 해결되지 않았습니다.
