# 감사 분석 결과의 출처 추적 및 검토 관리 설계

회계감사 데이터 분석에서는 결과 금액뿐 아니라 어떤 원본 자료와 계산 조건으로 결과가 생성되었는지 확인하는 것이 중요합니다.

이를 위해 원본 행 연결, 자료 버전 관리, 계산 근거 기록, 검토 이력 및 감사조서 출력을 지원하도록 설계하였습니다.

## 1. 출처 추적

- 결과 행별 Review_Record_ID를 CSV와 웹에 함께 부여합니다.
- 업로드 바이트 SHA-256, 자료 버전 ID, 파싱 후 표 해시, 실행 조건, Python 엔진 코드 해시를 기록합니다.
- 논리 원본 행을 조회할 수 있고 XLSX는 사용한 첫 시트 이름을 기록합니다. CSV 행 번호는 여러 줄 셀을 고려한 논리 레코드 번호입니다.
- GL 연도·기간·계정·사업단위·통화를 분리해 집계 입력을 연결합니다. TB 지표는 사용한 TB와 계정 분류 입력을 함께 연결합니다.
- JET는 탐지 행 또는 전표 구성행을 연결합니다. 저빈도·중복 규칙의 재수행에는 전체 모집단을 함께 사용합니다.
- 자금 대사는 양쪽 거래 ID, 재고는 품목별 기초·수불·로트 입력 범위를 연결합니다. 누적 수불은 해당 일자·원본 행까지의 입력을 연결합니다.
- 상태 source_rows=원본 행, group_inputs=집계 입력 범위, unavailable=연결 미확보 또는 해당 없음. 표별 연결 상태를 함께 기록합니다.
- 추적 시작점은 이번에 업로드한 GL/TB 등입니다. SAP 웹 변환 결과는 sap_lineage로 BSEG·BKPF 행을 연결합니다.

## 2. 자료·기간·버전

자료마다 이름, PBC 참조, 시작·종료 기간을 등록합니다. 자료 메모에는 사용자가 선언한 기간을 기록합니다. 실행을 시작하면 자료 정보는 고정됩니다.

동일 슬롯을 재업로드하면 이전 파일을 작업 만료까지 보관합니다. 전체 용량 80MB에 이전 버전도 합산하며 작업별 30개 자료 버전까지 허용합니다. 저장 경로에는 내부 식별자를 사용합니다. 작업 만료 또는 삭제 시 모든 버전·계산 결과·검토 이력도 삭제됩니다.

## 3. 비교 화면

- 분석 결과 표에서 전기·당기 수치와 누락 상태를 함께 확인합니다. 한쪽 연도 누락은 결측 상태로 표시합니다.
- 이전 버전과 현재 자료는 사용자가 입력한 유일 키로 비교합니다. 예: 회사코드+회계연도+전표번호+전표행 또는 Row_ID. 키 공백·중복은 비교 전 입력 이슈로 반환합니다.
- 문자열 기준 추가·삭제·변경 비교이며 100과 100.00도 표현 변경으로 표시합니다. 화면에서는 첫 25개 변경을 표시하며 API는 offset/limit 페이지를 지원합니다.
-  현재 XLSX 입력은 첫 시트만 분석합니다.

## 4. 기준서 참조와 검토 이력

기준/해설명, 발행기관, 판본, 문단, 적용일, 공식 출처 URL과 적용 사유를 등록하고 결과 행에 연결합니다. 사용자 등록·미검증으로 표시합니다. 참조 정보는 사용자 등록 방식입니다.

검토 상태·설명·증빙/PBC 참조·결론·연결 기준·서버 인증 사용자·시각을 기록합니다. 검토완료는 결론과 증빙 참조가 필요합니다. 변경 이력을 추가하며 revision 충돌은 409로 거절합니다.

분석 시점 ZIP은 고정된 결과와 review_snapshot.json을 포함합니다. 이후 검토 의견은 **최신 검토 이력 JSON**으로 별도 다운로드합니다. 이 파일의 run_id와 analysis_artifact_sha256으로 분석 ZIP과 연결합니다. ZIP에는 결과와 추적 메타데이터를 포함합니다. 민감한 값은 분석 결과나 명시적으로 매핑한 표에 포함될 수 있으므로 다운로드 파일은 사용자 보관 정책으로 관리합니다.

## 권한과 검증

작업·결과 API는 모드별 인증·회사 및 사용자 소유권·만료 검사를 적용하며 응답은 no-store입니다. 로컬 개발은 Bearer 토큰을 브라우저 메모리에 보관하고, 공개 데모는 방문자별 HttpOnly 쿠키를 사용합니다. health·세션 시작 등 공개 경로와 개별 예외는 security.py와 Backend README를 확인합니다. 업로드된 회계 데이터의 분석은 로컬 Python 엔진에서 수행합니다. KYC 공시 수집은 별도의 외부 API를 사용하는 기능이며, 해당 기능의 전송 범위는 별도 설정과 구현 기준을 따릅니다.

새 기능은 합성 데이터와 임시 저장소를 활용하여 단위 테스트 및 API 테스트를 수행하였습니다.

## 결과 ID의 범위

Review_Record_ID는 실행 ID·결과표·행 위치로 생성한 결과 식별자입니다. 실행·표 단위의 결과 식별자입니다. 원본 비교는 자료 버전·업무키·논리 행 번호를 사용합니다. 해시는 원본 동일성 확인에 활용합니다.
