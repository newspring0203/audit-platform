# 브라우저 시연 및 프로젝트 보고서 준비

## 보고서의 중심 흐름

공시 기반 회사 이해 → 원본 전처리·검증 → 목적별 분석 → 원본 추적·검토 기록 → 조서 다운로드.
기능별로 감사 목적, 입력 자료, 호출 함수, 처리 기준, 결과 화면, 후속 확인과 한계를 설명한다. 모든 분석을 하나의 회사 실제 데이터로 수행했다고 주장하지 않는다. 공개 공시와 합성 GL의 범위를 분명히 표시한다.

## SAP 브라우저 실행

1. 로컬 서버 재시작 후 브라우저 새로고침·개발용 토큰 연결.
2. 데이터 준비 → SAP 전처리. 회사·회계연도·원장·실적구분·버전을 실제 추출 명세에 맞게 입력.
3. 작업 생성 후 bseg, bkpf, glt0 파일 업로드. XLSX 첫 시트 또는 헤더 포함 CSV 지원. 파이프 구분 BKPF TXT 지원.
4. 분석 실행 후 gl, tb, nonbalancing_journals, gl_tb_reconciliation 등을 선택해 검토.
5. gl 행의 확인 버튼에서 원본 BSEG·BKPF 참조 확인.
6. 분석 조서 ZIP의 review/analysis/gl.csv 및 tb.csv를 후속 분석에 사용. 현재 다른 작업으로 자동 전달하지 않으므로 다운로드·재업로드 필요.
7. 분석적 검토에는 2개 연도 GL이 필요하다. SAP 한 연도 결과만으로 전기 비교가 완성되지는 않는다.

## SAP 범위와 코드 출처 설명

notebooks/reshape_rename_sap_data.ipynb에 있던 검증·결합·금액/날짜 변환·TB 누적 및 대사 로직을 sap.py의 함수로 분리해 웹 실행 경로에 연결했다. 기존 노트북은 보존했고 정답 자료로 두 경로의 GL·TB·대사 결과 일치를 검증한다. 기존 ADS 예제를 참고한 부분과 직접 추가한 검증·웹 연결·기록 기능을 구분해 설명한다. 파일의 존재만으로 독자 작성이나 독창성을 주장하지 않는다.

달력연도·금액 소수 2자리·예제 SAP 필드명 전제. 회사·연도·원장·실적구분·버전을 사용자가 지정하며 통화 기준은 원본 추출 명세와 대조해야 한다. 차대 불일치나 대사 차이가 있으면 생성 파일을 검토 없이 확정 모집단으로 사용하지 않는다. 모든 내부 보조 함수가 독립 메뉴인 것은 아니며, 실제 노출된 조건 범위만 시연한다. AI는 OpenAI 키·모델·서버 허용이 없으면 사용하지 않는다.

1. 문제 정의와 구현 범위

각 기능 화면은 입력 조건, 결과, 원본 추적을 각각 캡처한다. 결과 수치는 해당 실행 화면/CSV와 일치시킨다. 실제 API 검증과 합성 데이터 회귀 테스트를 구분한다. Word/PDF 제작은 화면·실행 결과를 확보한 뒤 진행한다.

## 추가된 조회 회신 검토

매출채권 조회 회신과 금융기관 조회 회신 메뉴를 추가했다. `confirmations.py`의 공통 비교 엔진을 사용하며 각 메뉴에서 ledger·requests·replies를 업로드한다. `docs/confirmation_review.md`에 입력·결과·시연 기준을 정리했다. 단위·대상·통화·기준일 일치 검증, 미회신/부분/이의 회신 구분, 금융기관 조건 검토, 원본 행 추적과 미검토 기록을 제공한다. 금액이 같아도 조건 차이가 있으면 검토 목록에 남긴다. 실제 조회서 발송·진위 확인이나 외부 조회 절차 완료를 의미하지 않는다.
