# 캐시와 임시 처리 정책

## 구분

임시 작업 저장은 처리·재다운로드를 위한 단기 보관이며, 다른 요청에서 분석 결과를 재사용하는 캐시와 다릅니다.

| 자료 | 현재 정책 |
|---|---|
| 고객 원본·분석 결과·조서·오류 본문 | 공유 캐시 없음. HTTP 응답은 private, no-store |
| 다운로드 ZIP·인증 실패·API 오류 | no-store. ETag/Last-Modified 조건부 다운로드를 사용하지 않음 |
| 공개 DART 원문·회사 목록 | 영구/공유 캐시 비활성. 수집 작업 내부의 회사 목록 재사용만 허용 |
| AI 요약 | 사용자별 작업 결과. 공개 공시 기반이어도 공유 캐시하지 않음 |
| 정적 JS/CSS | 프론트엔드 구현 후 해시 버전 파일만 별도 캐시 가능 |
| 인증·소유권 | 서버가 매 요청 확인. 소유자 확인 결과를 HTTP 캐시로 우회하지 않음 |

공개 공시 캐시를 추후 추가하면 허용된 공식 API의 공개 응답만 전용 저장소에 넣습니다. 회사 고유번호·접수번호·원문 해시·정정 여부·파서 버전·TTL로 구분하고 API 키·인증된 사용자 정보는 키나 값에 넣지 않습니다. 고객 자료와 같은 저장소나 조회 API를 사용하지 않습니다. AI 요약의 공용 재사용은 현재 범위에 없습니다.

## 임시 작업 보관

기본 생성 후 1시간에 만료합니다. 사용자에게 expires_at을 제공하고 만료 후 접근은 즉시 차단합니다. 30초 주기·서버 시작·새 작업 생성 때 정리합니다. 실행 중인 작업은 프로세스를 종료한 뒤 지우고, 삭제 실패 시 기록을 남겨 재시도합니다. 서버 종료 중에는 정리가 동작하지 않으므로 운영에서는 외부 정리 작업과 경보가 필요합니다.

원본·조서·미리보기·임시 파일·디버그 파일을 모두 해당 작업 영역에 둡니다. 원본 파일명은 저장 파일명으로 쓰지 않습니다. 최소 보안 이벤트의 개발 기본 보관은 24시간입니다. 실제 감사자료 보존 의무를 정한 값이 아니며 조직 정책으로 별도 결정해야 합니다.

기존 학습용 data/raw와 outputs 파일은 이 정책으로 삭제하지 않습니다. 새 API 작업의 .runtime 영역만 대상입니다. 민감한 실제 자료를 예전 노트북·CLI에서 실행하면 해당 도구의 기존 로컬 저장 동작이 적용됩니다.

## 주변 시스템

no-store 헤더만으로 CDN·리버스 프록시·백업·오류 수집·세션 리플레이까지 통제되지는 않습니다. 운영에서 /api와 다운로드 경로의 캐시를 우회하고 요청/응답 본문 로깅을 끄며 프록시 임시 파일·스냅샷·백업 보존 정책도 맞춰야 합니다.

프론트엔드에서는 결과·파일·접근 토큰을 localStorage/IndexedDB/Service Worker 캐시에 넣지 않고, 민감한 화면의 세션 리플레이·분석 이벤트에 원문을 보내지 않는 방향으로 구현합니다. 현재 프론트엔드는 미구현입니다.

CSV는 다운로드용 문자열 수식을 이스케이프합니다. 원본과 분석 DataFrame 값은 그대로 두고, CSV에서 =,+,@ 또는 계산식처럼 보이는 문자열에 작은따옴표를 붙입니다. 실제 음수 숫자는 유지합니다. Excel 결과는 텍스트/숫자 타입을 구분합니다.

파일 삭제는 OS 파일 제거이며 백업·SSD의 물리적 보안 소거를 보증하지 않습니다. 사용자가 이미 다운로드한 복사본은 서버가 회수할 수 없습니다.
