# 작업 보관과 캐시 정책

## 자료별 처리

| 자료 | 처리 방식 |
|---|---|
| 원본·분석 결과·조서·오류 응답 | 작업별 비공개 보관, HTTP `private, no-store` |
| 다운로드 ZIP | 권한·만료 확인 후 제공, `no-store` |
| 공개 DART 자료 | 수집 작업 내부에서 회사 목록 재사용 |
| AI 요약 | 사용자별 작업 결과로 관리 |
| 정적 JS·CSS | 고객 자료와 분리된 정적 리소스 |
| 인증·소유권 | 요청마다 서버에서 검사 |

## 임시 보관

- 생성 후 기본 1시간에 만료하고 `expires_at` 제공.
- 만료 즉시 접근 차단, 서버 실행 중 30초 주기·시작 시·새 작업 생성 시 정리.
- 실행 중 작업은 프로세스 종료 후 삭제, 삭제 실패는 기록·재시도.
- 원본·결과·미리보기·임시 파일은 전용 작업 영역에 보관.
- 보안 이벤트의 개발 기본 보관은 24시간.

이 정책은 웹 `.runtime`에 적용합니다. 로컬 `data/raw`·`outputs`, 다운로드 사본과 백업은 각 보관 정책으로 관리합니다. 삭제 방식은 OS 파일 제거이며 운영 보관·삭제 기준은 조직 정책에 연결합니다.

## 브라우저·출력

로컬 개발용 Bearer 토큰은 메모리, 공개 데모는 HttpOnly 쿠키로 관리합니다. 결과 조회와 다운로드는 서버 권한 검사 후 처리합니다.

CSV 수식 방지 처리는 다운로드 복사본에 적용하고 원본 DataFrame과 실제 음수 숫자는 보존합니다. Excel은 텍스트·숫자 타입을 구분합니다.

## 운영 확장

프록시·CDN의 API 캐시 우회, 본문 로깅 범위, 백업·스냅샷 보관, 외부 정리 스케줄러·삭제 실패 경보를 운영 구성과 함께 관리합니다.
