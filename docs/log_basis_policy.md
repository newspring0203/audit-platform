# 로그 대사 기준과 검토 결과

## 서비스 동작

계산 전제조건이 없으면 해당 계산은 하지 않되 사용자에게 결과·조서를 제공합니다. 기준 미확보를 회계 오류나 차이 없음으로 표시하지 않습니다. GL 단독 검사는 해당 입력 범위에서 계속할 수 있으며 이것이 모집단 완전성 검증을 뜻하지는 않습니다.

## 상태

- basis_information_missing: 금액·통화·범위의 근거 또는 확인·검토 정보 미확보.
- basis_not_comparable: 서로 다른 금액 필드·통화 기준·범위.
- basis_evidence_invalid: 근거 파일이나 검토 입력 변경·유효하지 않은 참조.
- matched: 기준 게이트 통과 후 해당 대사에서 차이 없음.
- differences_found: 기준 게이트 통과 후 해당 대사에서 차이 발생.

미실행의 차이 건수는 null이고 관련 결과표는 비어 있습니다. 빈 결과표를 정상으로 해석하지 않도록 상태와 사유를 함께 제공합니다. 로그 모집단 비교도 확인 범위가 불명확하면 미실행입니다.

## 확인서

LogBasisConfirmation에는 양쪽 원본 금액 필드, 기능통화/그룹통화 기준, 회사·회계연도·원장·기간·추출 설명, 입력 GL/로그 지문, 확인자·검토자·검토일, 통화 확인 방식, 근거 파일이 필요합니다.

EvidenceFile은 전용 data/evidence 폴더 아래의 상대 경로·SHA-256·설명을 가집니다. 파일이 없거나 변경됐으면 대사를 하지 않습니다. 검토 후 입력 GL·로그의 컬럼·행 순서·값이 바뀌어도 재확인이 필요합니다.

통화 컬럼이 없는 자료는 확인 근거로 단일 통화임을 검토한 경우에만 confirmed_single_currency 방식으로 처리합니다. 기존 로그에 다른 통화가 있으면 덮어쓰지 않습니다. 통화 코드 선택이나 confirmed=True만으로는 게이트를 통과하지 않습니다. 원본 데이터를 수정하지 않습니다.

첨부 파일의 존재·해시와 검토 기록이 있다는 사실이 그 내용의 진실성·적정성을 보증하지 않습니다. 현재는 로컬 Python 확인 모델이며, 웹 사용자 인증·승인 권한·변경 불가능한 승인 이력은 아직 없습니다. 감사인의 증거 평가를 대신하거나 PCAOB/AICPA 전체 준수를 인증하지 않습니다.

## 페이지 공통 처리

execute_analysis(name, operation)는 입력 검사·파일 읽기·계산을 operation으로 감쌉니다. 예상 입력 오류는 표로 반환하고, 내부 오류는 세부 경로·키를 노출하지 않는 시스템 이슈로 반환합니다. execute_batch는 독립 모듈 하나가 실패해도 나머지 결과를 수집합니다.

completed / completed_with_limitations / not_executed_input_issue / not_executed_system_issue를 구분합니다. 모든 결과에 미검토 상태를 유지합니다. generate_working_paper는 계산 미실행과 로그 대사 미실행을 조서 앞부분에 표시합니다. 파일 저장 자체가 실패하는 경우에는 별도 서비스 저장 오류 처리가 필요합니다.

## 과거 결과

잘못된 단일 통화 가정으로 생성된 과거 결과 폴더에 validity.json과 사용 제한 안내를 남깁니다. 과거 조서는 원문 백업을 보존하고 사용 제한 안내를 표시합니다. 검증된 금액 대사 증거로 사용하지 않습니다.
