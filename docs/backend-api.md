# Backend API · 인증과 자료 처리

[백엔드 개요](../backend/README.md) · [배포 설정](deployment.md)

## API 흐름

| 메서드 | 경로 | 용도 |
|---|---|---|
| GET | `/health` | 서버 상태 |
| GET | `/deployment-info` | 환경과 전체 기능 목록 |
| POST | `/demo/session` | 공개 방문자 세션 발급 |
| GET | `/api/features` | 기능·입력 자료·분석 조건 정의 |
| POST | `/api/jobs` | 사용자 조건으로 작업 생성 |
| PUT | `/api/jobs/{job_id}/inputs/{slot}` | 원본 바이트 업로드. `X-Filename` 필수 |
| POST | `/api/jobs/{job_id}/run` | 분석 실행. KYC는 별도 키 본문 사용 |
| GET | `/api/jobs/{job_id}` | 진행 상태·결과 식별자 |
| GET | `/api/jobs/{job_id}/review` | 결과와 검토 정보 |
| GET | `/api/jobs/{job_id}/downloads/{artifact_id}` | 인증·소유권 확인 후 ZIP 제공 |
| DELETE | `/api/jobs/{job_id}` | 작업 중지 및 자료 삭제 |
| POST | `/api/logout` | 세션 폐기 |

공개 환경의 상태 변경 요청에는 정확한 `Origin`과 `X-Audit-Request: 1`이 필요합니다. 인증은 서버 발급 HttpOnly 쿠키로 처리합니다. 작업·업로드·다운로드는 소유 방문자의 권한으로 처리합니다.

일반 파일 분석은 작업 생성 → 자료 업로드 → 실행 순서입니다. 작업 조건은 `parameters`, API 키는 별도 실행 본문으로 구분합니다. `metadata.execution_status`와 미실행 사유로 세부 수행 결과를 확인합니다.

## 방문자 OpenDART 키 처리

KYC 작업의 실행 요청은 `POST /api/jobs/{job_id}/run`에 JSON 객체 `{ "dart_api_key": "본인이 발급받은 인증키" }`를 전달합니다. 키는 전용 입력란 또는 로컬 설정에서 관리합니다.

- 본인 작업 소유권을 먼저 확인하고, 요청 크기와 키 형식을 검사합니다.
- 공개 환경에서는 방문자 키를 명시적으로 요구합니다. 해당 방문자가 제공한 키로 실행합니다.
- 키는 실행 중 메모리에서 처리하고 저장 항목은 분석 조건과 결과로 제한합니다.
- 분석 worker에는 명령줄 인자나 환경변수가 아닌 익명 표준입력 파이프로 전달합니다. 해당 작업에서만 메모리로 사용합니다.
- OpenDART의 고정 HTTPS API로만 전송하고 리다이렉트는 차단합니다. 공급자 오류는 키를 제외한 사용자용 코드로 기록합니다.
- 브라우저 입력란은 실행 요청 시 비우며 현재 화면 메모리에서 처리합니다. 입력 후 실행 전까지는 해당 화면 메모리에 존재합니다.

키는 HTTPS 요청과 분석 프로세스의 메모리에서 일시적으로 처리합니다. 서버 재시작 후에는 새 작업에서 다시 입력합니다. 로컬에서는 `.env` 설정도 사용할 수 있습니다.

OpenDART 연동은 키 입력 검증과 모의 API 응답으로 테스트했습니다. 유효한 사용자 키를 통한 실제 조회는 추가 확인 항목입니다. 선택적 AI 요약은 `AUDIT_ALLOW_AI=true` 및 서버의 OpenAI 설정이 별도로 필요하며 기본 비활성화입니다.

## 파일과 출력 정책

CSV·TXT·XLSX만 허용하며, 파일당 기본 20 MiB·작업 입력 합계 80 MiB를 제한합니다. XLSX 구조·압축 해제 용량·매크로·외부 링크·DTD/엔티티를 검사합니다. 원본과 결과는 웹 정적 경로가 아닌 전용 임시 저장소에 보관합니다.

기본 작업 TTL은 생성 후 3600초입니다. 만료 시 즉시 접근을 차단하고, 서버 실행 중 30초 간격 및 서버 시작 시 정리합니다. 방문자당 활성 작업은 기본 3개, 전체 20개이며 요청 수·동시 분석 수·실행 시간도 제한합니다. 무료 Render의 휴면·재시작·재배포 시 파일과 세션이 먼저 사라질 수 있습니다.

조서 ZIP은 CSV·JSON·Markdown과 검토 스냅샷을 포함합니다. XLSX 조서는 별도의 Node/Excel 렌더러를 설정한 환경에서만 생성되며 기본 배포 출력은 CSV·JSON·Markdown입니다. 다운로드한 파일은 사용자 측에서 관리합니다.
