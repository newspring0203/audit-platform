# 시연 파일 넣는 순서

모든 입력은 `data/demo/v1`의 합성 자료입니다. 실제 회사·고객 자료가 아닙니다. VS Code 탐색기에서 이 폴더를 펼쳐 놓고 시작하세요. 파일 선택 창에서는 ⌘⇧G를 눌러 `/Users/saebom/audit-platform/data/demo/v1`을 입력해도 됩니다.

## 먼저 찍을 추천 시나리오: 분석적 검토

1. 왼쪽 **분석적 검토** 선택.
2. 당기 2026 / 전기 2025 / 증감률 30 / TB 기간 10 입력.
3. 합성 TB 부호 기준은 차변 양수·대변 음수이므로 해당 확인값 선택. 실제 파일은 확인 없이 선택하지 않습니다.
4. **이 조건으로 작업 만들기** 클릭.
5. gl → `gl_comparison.csv`, tb → `tb.csv`, account_mapping → `account_mapping.csv` 선택하여 자동 업로드.
6. 파일 선택 시 자동 업로드됩니다. 자료 요청 참조는 `DEMO-GL-01`, `DEMO-TB-01`, `DEMO-MAP-01`로 입력할 수 있습니다. 합성 시연에서 임의로 붙인 관리 번호이며 실제 증빙 확인을 뜻하지 않습니다. 파일의 메모 기간은 비워도 됩니다. 특히 TB는 2025년 10기와 2026년 10기의 두 시점 잔액이므로 하나의 연속 기간으로 입력하지 않습니다. 이 시점은 분석 조건에서 지정합니다.
7. **분석 실행** → 결과 탭: 비교 계정 2개, 검토 후보 2개. 계정 1000 순변동 3,000→7,000, 계정 4000 -3,000→-7,000. GL 순변동은 TB 잔액과 다릅니다.
8. 표를 financial_ratios로 바꾸면 유동비율 2025년 4배, 2026년 5배를 확인합니다.
9. year_comparison의 확인 버튼 → 검토 기록 탭 → gl 원본 → 원본 행과 산식 확인.
10. 검토중 / 증빙 참조 `DEMO-GL-01` / 설명 “합성 입력의 9·10월 거래를 비교함” / 결론 “추가 증빙 확인 필요”를 입력하고 저장.
11. 분석 조서 ZIP과 최신 검토 이력을 각각 다운로드. 다운로드한 결과는 새 입력 슬롯에 무작정 다시 올리지 않습니다.

## 다른 기능별 정확한 입력

| 재고 분석 | movements → movements.csv / opening → opening.csv / lot_snapshot → lot_snapshot.csv | 기준일 2026-10-31 / 장기 180 | 기간 중 음수 1건, 기말 음수 0건, 장기 미출고 후보 1개. 로트 수량 대사 후 연령 집계 |

CSV는 UTF-8 BOM이며 코드·날짜는 텍스트로 읽도록 준비했습니다. Excel에서 열었다 저장하면 선행 0이나 날짜 형식이 바뀔 수 있으므로 시연에는 원본 파일을 그대로 올리세요. QuickBooks CSV 대체 파일도 있으나 촬영에는 Excel을 권장합니다.

## 기준서 등록·선택까지 직접 테스트하기

이 목록은 직접 타이핑하는 입력칸이 아닙니다. 먼저 기준서를 등록하면 체크박스가 나타납니다. 여러 항목을 동시에 체크할 수 있습니다.

1. 시연 안내대로 분석 실행을 완료합니다.
2. 분석 결과의 특정 행에서 **확인**을 눌러 검토 기록을 엽니다.
3. **기준서 등록하기**를 누르면 아래 등록 양식으로 이동합니다.
4. 기능 확인만 할 때는 다음처럼 가상 참조임을 명시합니다. 실제 기준서 문단으로 사용하지 않습니다.

| 입력 | 테스트 값 |
|---|---|
| 기준 / 해설명 | 시연용 가상 기준서 A (공식 기준 아님) |
| 발행기관 | DEMO |
| 판본 / 개정일 | TEST-2026 |
| 문단 번호 | DEMO-01 |
| 적용 시작일 | 비워도 됨 |
| 공식 출처 URL | 비워둠 |
| 이 거래에 적용하는 이유 | 등록·선택 기능 테스트용이며 실제 회계기준으로 적용하지 않습니다. |

5. **참조 등록**을 누릅니다. 위의 연결 목록에 체크박스가 나타납니다.
6. 두 개 선택을 확인하려면 가상 기준서 B / DEMO-02로 하나 더 등록합니다.
7. 연결할 항목을 체크하고, 검토 상태는 **검토중**으로 둡니다. 증빙 참조 DEMO-01과 기능 테스트용 결론을 입력한 뒤 **검토 기록 저장**을 누릅니다.
8. **최신 검토 이력**을 다운로드하여 reference_ids에 선택한 항목이 연결됐는지 확인합니다. 기록은 해당 분석 작업에 종속됩니다. 새 작업에서는 다시 등록해야 합니다.

실무 기준을 연결할 때는 실제 확인한 기준서의 발행기관·판본·문단·공식 출처·적용 사유를 입력하세요. 가상 참조를 실제 감사 근거처럼 제출하지 않습니다.

## 자동 검증 범위

전체 184개 테스트 통과. 7개 로컬 기능은 각각 시연 파일 업로드 → 실행 → 결과 조회 → ZIP 다운로드 → 기준서 2개 등록·연결·검토 이력 저장까지 API로 검증했습니다. 브라우저에서도 빈 목록 안내 → 가상 참조 등록 → 체크박스 선택 → 저장 → 내보내기 기록 연결을 확인했습니다.

KYC는 외부 API를 사용하지 않은 가상 공시의 worker 처리만 검증했습니다. 실제 OpenDART 수집과 AI 호출이 성공했다는 뜻은 아닙니다. 실자료 다양성·감사 판단의 적정성 역시 별도 검증 대상입니다.

## 자동 저장 방식

분석 조건 설정 → 작업 만들기 → 파일 선택(자동 업로드) → 필요하면 자료 메모 기간·PBC 입력(자동 저장) → 저장 완료 표시 확인 → 분석 실행. 자료 업로드 버튼은 없습니다. 여러 슬롯은 순차 저장되며 저장 중·실패·기간 입력 미완성 상태에서는 분석을 실행할 수 없습니다.

PBC는 Prepared/Provided By Client라는 표현으로 쓰이는 고객 제공 자료의 요청·수령 목록을 뜻합니다. 이 화면의 PBC 참조는 그 목록에서 자료를 찾을 관리 번호입니다. 분석 금액 계산에는 쓰이지 않고, 자료 요청 체계가 없는 학습·시연을 위해 선택 사항입니다. 회계기준 참조 문단이나 실제 증빙 검토 완료 여부와는 별개입니다.
